# Spenza — WordPress → Astro migration

A faithful Astro rebuild of the Spenza WordPress site (`preprod.spenza.com`).

The site is mirrored rather than reinterpreted: every page ships the exact
Elementor/Astra markup and stylesheet set the WordPress page served, so the UI
and animations match. WordPress' jQuery runtime is replaced by a small vanilla
shim, and a thin polish layer smooths the motion.

## Commands

| Command | Action |
| :------ | :----- |
| `npm run dev` | Dev server on <http://localhost:4321> |
| `npm run build` | Static build to `./dist/` |
| `npm run preview` | Preview the build |
| `npm run wp:audit` | Verify every asset each mirrored page references resolves |
| `npm run wp:audit-links` | Verify every internal link resolves |

## Architecture

```
src/
  layouts/WpLayout.astro     Mirrored pages: WP stylesheets + chrome + shim
  layouts/BaseLayout.astro   Hand-built pages (the /preview rebuild)
  partials/<slug>.html       Extracted Elementor page content
  partials/chrome/           Header + footer templates (shared by all pages)
  partials/archives/         Category / author / date archives
  data/wp-styles.json        Per-page stylesheet list, in WordPress' order
  data/wp-inline-styles.json Per-page bundle of extracted inline <style> CSS
  data/wp-scripts.json       Per-page custom site scripts + JSON-LD
  data/wp-pages.json         Titles, meta descriptions, body classes, routes
  data/blog-categories.ts    Category name → URL slug map
public/
  wp-assets/                 Mirrored Elementor/Astra CSS, fonts, icons, WebP
  wp-content/uploads/        Mirrored media
  scripts/wp-shim.js         Replaces Elementor's jQuery frontend runtime
  scripts/page/<slug>.js     The site's own inline scripts, per page
```

### Why the data files exist

Elementor's cascade is order-dependent, so `wp-styles.json` preserves the exact
stylesheet order each page loaded. Astra's dynamic theme CSS and the site's
`wp-custom-css` only exist as inline `<style>` blocks — including some in the
**body**, which carry real layout rules (the expanding case-study row) — so they
are extracted into `wp-inline-styles.json` bundles. Astra and Elementor also key
styling off body classes, which is why those are mirrored verbatim.

### URL structure

Blog posts live at their WordPress URLs, `/<category>/<slug>/` (e.g.
`/telecom/what-is-mvno/`), generated by `src/pages/[category]/[slug].astro`.
`/blog/<slug>/` is kept as a redirect, matching WordPress' 301.

## Re-syncing from WordPress

The pipeline is reproducible. It reads `.wp-cache/cookies.txt` (a logged-in
WordPress session — `.wp-cache/` is gitignored and must never be committed).

```sh
npm run wp:resync        # assets → content → inline CSS → WebP → scripts → pages
npm run wp:archives      # category / author / date archives
npm run wp:post-template # the single-post style bundle
npm run wp:blog-media    # blog images + localise markdown URLs
```

Individual steps are also available: `wp:assets`, `wp:content`, `wp:inline-css`,
`wp:webp`, `wp:scripts`, `wp:pages`.

After any resync, run both audits — they are the regression net:

```sh
npm run build && npm run wp:audit && npm run wp:audit-links
```

## Known gaps

- **Forms don't submit.** Gravity Forms markup is preserved but its runtime is
  not; submissions need a backend or a form service.
- **No analytics or chat.** Tracking tags (GA, LinkedIn, Apollo, Vector) and the
  chat widget were deliberately not carried over.
- **`proxima-nova` is never served.** Headings request it, but WordPress loads it
  from a Google Fonts URL that 403s — it only renders where the font is installed
  locally. Manrope carries the fallback.
- **Content still points at preprod.** Some blog posts link to
  `api.preprod.spenza.com`, `telematics.preprod.spenza.com` and
  `@preprod.spenza.com` addresses.
- **Anchor links are dead.** `#products`, `#solutions`, `#case-studies` have no
  matching element — true on the live WordPress site as well.
